Implemented on `59ff40e`, uncommitted, on the Windows host; record in `evidence/webview-integration/stage-3.md`, built behavior in `docs/current/webview.md#windows-host`. Nothing is committed.

- **The RDP session was disconnected while the host was built**, so nothing needing input injection or a visible screen could run then: the spike's adjusted `error-pages` rerun (`SendInput: Access is denied`; attempt kept as `error-pages-rerun-attempt-1-disconnected/`), screen captures (`BitBlt: Access is denied`) and the size/move case. Everything else runs without a connected desktop because the production error actions are driven through navigation policy (`action LABEL retry|start` navigates to the action URI), not clicks. Michael connected the session later the same evening and the owed runs were made then: the spike scenario passed (`error-pages-rerun/`) and the matrix passed 16/16 (`stage-3/run-connected/`).
- **The Windows attachment is portable Go over an `api` function table** (`internal/platform/webview2/browser.go`), bound to COM only in `native_windows_amd64.go`; the state machine's tests run on any platform, like webkit's. Keep new native calls behind `api` fields, or the Linux side loses the ability to run them.
- **Shared audit type**: `webkit.Audit` is now an alias of `platform.BrowserAudit`, so the example's audition interface serves both hosts. This changes the Linux browser binary; the Linux return must rebuild and rerun its matrix (the example's probe also changed: see below).
- **Chromium reports an SVG `<img>`'s intrinsic width (48), WebKit the attribute width (24).** The example probe's image check is now `naturalWidth > 0` plus the recorded width; Linux's assertion of `img` still holds. Not a product change.
- **In-process origin is canonical `https://dfx2.invalid:443`** (the `origin` package adds the effective port), so the first navigation to `https://dfx2.invalid/` is allowed; the first native smoke run refused it with the port-less constant. A handler sees `Host` `dfx2.invalid:443`.
- **The Winsock reset errno**: `TestLoopbackProtocolRejectionsStayOutsideApplicationResponses/oversized` failed on Windows because `syscall.ECONNRESET` is a placeholder there and Winsock reports `WSAECONNRESET` (10054). The test's reset acceptance now recognizes both through a per-platform helper; the assertion is unchanged. The first Windows run of the stage 1 endpoint suite was this one.
- **Response bodies are a host-implemented agile `IStream`**, not `SHCreateMemStream`: its final release by the engine is what reports the request released, so the adapter's native-copy accounting is exact. A clone shares the body and release. If WebView2 ever keeps a stream forever, the endpoint, not the attachment, holds the window (streams do not use the parent).
- **Dropped completion handlers settle through their final `Release`**: `comRelease` runs `dropped` when a handler the engine took (`taken`) reaches zero without having been invoked. The host's own initial reference never counts as the engine's, so a failed `add_`/`Create` does not fire it.
- **Browser-process exit sometimes takes ~6.5 s** after `Controller.Close` (seen once in the spike, once here, in the `quit`-with-window-open path); the supervisor's five-second shutdown diagnostic then appears on stderr by design. The driver records those lines as diagnostics, not failures. Not understood; not a timeout to add.
- **Decided not to extract webkit's policy into a shared package**: the Windows mechanics differ (method from the document request, correlation by generation, `.invalid` action origin), the overlap is ~60 lines, and keeping webkit untouched beyond the alias keeps Linux evidence comparable.
- **The embedded loader needs a `.gitignore` negation** (`!/internal/platform/webview2/sdk/WebView2Loader.dll`): the root rule ignores every DLL. The 164 KB binary is now a tracked file; Michael's commit carries it.
- **`CreateCoreWebView2EnvironmentWithOptions` completed its handler before returning** in the production host, every time (the `opened` event shows one creation pending and no events when `Open` returned: the environment was done and the controller in flight). The spike timed the callback asynchronously; here the loader's call pumps or completes inline. The attachment registers routing before every creation call, so it worked unnoticed until the staged-close audition found the "environment" stage already passed from the example's side. `AuditionCloseAt` closes at once for a stage whose creation is in flight, so "controller" is the earliest stage reachable natively after Open; a close during environment creation is covered only by the modeled tests, and the matrix records which stages were reachable.
- **Start a Win32 size/move loop by dragging the caption with `SendInput`, not by `SC_MOVE` by message**: `SendMessage(WM_SYSCOMMAND, SC_MOVE|2)` to the shell started no loop even in the connected session (the window was never the active one; not pursued further). The matrix's `size_move` case now does what the mixer arc's `desk` driver does: raise the window, hit-test a caption point, press, move, release; the backend's `ModalLoops` counter decides whether a loop ran, and a refused injection classifies the case untested with the session state. A screen copy can fail once with `GetDIBits` returning no lines right after the window was displayed; the driver retries the copy twice.
- **Terminus is not on this host**; the review runs on the Linux return, as the earlier handoffs said.
- **Audit events carry `Seq`** (both hosts): the 64-event ring made the driver's position-based waits miss events in long cases. Drivers wait by sequence number now; the Linux driver still waits by position and works only because its cases are short.
