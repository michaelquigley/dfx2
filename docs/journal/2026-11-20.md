## Stage 3 return corrections (uncommitted, not accepted)

The WebView2 body reader, metadata bound and notice retention are implemented on Linux. They are verified only by modeled COM tests and cross-compilation. Native Windows validation is the next step; see the handoff at the end of `evidence/webview-integration/stage-3.md`.

- **The transfer reserve is now one metadata limit (was half).** WebView2's converted strings didn't fit the old reserve. The reserve sits in the shared endpoint, so the Linux browser binary changed too. It also raises the smallest `Buffers` value `Normalize` accepts. Michael has not ruled on this; don't shrink the reserve back without moving the conversion.
- **An unsupported stream aborts the request.** A non-agile stream, a failed `get_Content`, a failed COM initialization and a failed read all give the page a network error. None of them gets a fixed status. The open policy choice in the probe review was settled this way because it needs no response body. Michael may still choose otherwise.
- **The `ReadableStream` upload contract is still undecided.** The production `request-content` event, together with the probe page's `emptyPost` and `streamUpload` runs, exists to settle it on Windows. Don't write the contract from the spike's conflated log.
- **Oversized in-process metadata skips the origin check and the navigation record.** The URI is never converted, so the 431 is answered from the measured size alone. This is deliberate.
- **The `browser_test.go` fake must stay goroutine-safe.** Workers call `n.streamRead` and `n.post` off the test goroutine. Use `awaitPost` (wait without running) when a test must act between a worker's post and the UI handling it; `pump` runs posted work first.
- **`pkill -f` on the matrix's own command line kills the calling shell.** Stop a background matrix through its task instead.
- **Body-read stop is a terminal claim state, not just the closed grant channel.** `range` still delivers a value buffered before `close`. Every return from claimed to idle must be a compare-and-swap, or it can overwrite a stop. Tests that close "during a read" must first `awaitRead`: a close before the claim now correctly reads nothing.
- **`runWorker` (`worker.go`) owns the body worker's single completion report, and the Windows binding must keep calling it.** Inlining the COM calls back into `startWorker` would bypass the only ordering the tests can see. The regression holds the fake inside its injected `CoUninitialize`.
- **In `webview2`, report request releases through `b.release`, never `b.host.RequestReleased` directly.** Only `readFinished` calls it directly, to pay an owed release. A direct call on any other path frees the endpoint slot while a body worker is still tearing down. Michael rejected extending the endpoint's read reservation on both platforms instead, since it could change admission under byte pressure.
- **Audit events must not keep request strings.** The browser's event ring outlives the request call and isn't charged against `Buffers`. `request-content` therefore carries only the getter's result, and the Windows driver matches it by sequence mark. The older URI-bearing events (`blocked` and others) are left as they were, pending the inbox defect for them.
- **The native close evidence is `claimed-reads` (stops that found `readClaimed`), never `len(b.reads)`.** A registered reader may be leaving COM. `body_close` sets untested only after every attempt's close, observation and drain succeeded, because the matrix summary ignores failures on untested cases.
- **An empty `children` list in the Linux matrix's host records means no child exit status was observed, not that children exited cleanly.** Under X11 this holds for 8 of 15 hosts per session (7 in the return run). Only the final remaining-descendants check covers them. The reason is still open: no driver change was made, and no `bwrap` child is reaped under X11.
- **WebView2 teardown now waits for `b.streams == 0`, which makes the count load-bearing.** A response stream is counted at creation, and its final release is the only decrement. That covers a failed `CreateWebResourceResponse`, where the host's own release is final. Don't move the increment after the response succeeds: the gate would hang at −1.
- **WebView2's exit-kind getter's HRESULT is load-bearing.** Its zeroed output reads as normal, which would hide a crash during close. Browser-process failures go through `browserFailure`, which reports once across `ProcessFailed` and the exit. Renderer failures bypass it on purpose.
- **`BrowserRequest.BodyLength` is the declaration, and `NoBody` says no stream exists; a zero value of `NoBody` means "a stream may be present".** A test or adapter that builds a bodyless request must set `NoBody`, or the endpoint now owes it a one-byte read. WebView2 sets `NoBody` only after a successful `get_Content`. A failed getter must stay an abort.
- **A deferred trailing pointer move may coalesce with newer motion after its frame ends; this is intended (T4).** Deferred motion carries no state. Only edges do (a deferred fader press, a validated checkbox release), and edges never coalesce. Don't "protect" the unconsumed suffix from coalescing without a contract reason. Michael chose a documentation clarification only, with no pinning test.
- **Loopback deliberately drops a handler's 1xx responses other than 101 (U2).** Michael picked the simpler fix over attaching the CSP to each 1xx. Re-adding Early Hints would need the policy on each informational response and the header map restored afterwards, because net/http carries that map into the final response.
