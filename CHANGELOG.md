# Changelog

## Unreleased

- FEATURE: The mixer can open native and browser views over one application-owned model in in-process, loopback and attach modes. Both use the ordered command path and pending-edit policy; the native-only default remains. The webview integration arc is accepted at `a889a10`, with native and manual evidence on both hosts and a later checkbox reconciliation fix covered by the focused Node check. See the [stage 4 record](evidence/webview-integration/stage-4.md) for limits and deferred findings.

- FEATURE: Windows/amd64 hosts `webview` windows in the system WebView2 Runtime without cgo, in all three modes, from one executable: the pinned loader and its notices are embedded, extracted, verified and loaded on the first browser window and unloaded after the last; each window has a fresh profile and browser process, deleted only after that process exits; native interception of every request plus the framework security policy confine owned windows; the loopback credential is installed and confirmed through the native cookie manager before navigation; in-process responses are served through a host-implemented `IStream` whose release ends the request; a framework load-failure page offers Retry only for known GETs, correlated by navigation generation; browser- and render-process failures are fatal. See [webview.md](docs/current/webview.md#windows-host).

- FEATURE: Linux/amd64 hosts `webview` windows in the system WebKitGTK 4.1 without cgo, in all three modes: per-window ephemeral sessions, a native content filter plus the framework security policy confining owned windows, the loopback credential installed before navigation, bounded asynchronous in-process requests, a framework load-failure page with Retry only for known GETs, and fatal browser-process failures. Libraries load on the first browser window. Linux applications must set `webview.Options.LinuxGCSignal`, a real-time signal reserved for JavaScriptCore's garbage collector. The new `webview` example auditions it. See [webview.md](docs/current/webview.md#linux-host).

- FEATURE: The `webview` package opens browser windows that share the application lifetime, with an explicit `InProcess`, `Loopback` or `Attach` mode and no fallback between them. Its portable contracts are built and tested against fake native seams: the finite in-process `http.Handler` adapter with reserved request, response, metadata, admission and aggregate limits; the window-owned loopback server with a per-window HttpOnly credential, Host/Origin checks, connection and handler limits and streaming; a framework content security policy on every owned response; and browser, endpoint and cleanup ownership that keeps `Done` and `Run` pending until everything admitted has returned. At stage 1, `Open` refused with `ErrUnsupportedContent` on all platforms; the later Linux and Windows hosts are described above. See [webview.md](docs/current/webview.md).

- FIX: Paragraph caches own their UTF-8 keys and charge them against the existing budget, including through rewraps and eviction; substring keys no longer retain larger caller allocations.

- FIX: GTK painting checks Cairo context errors and propagates them through the application cancellation and drain path to `Run`, preserving a deferred dispatch wake so shutdown can finish.

- FEATURE: Windows/amd64 implements UI content presentation through `VirtualAlloc`-backed GDI and delivers bounded dispatch turns during native size and move loops, so frames and posted callbacks keep advancing for every window, with no timer running while idle. A core guard refuses any nested dispatch turn. Native [Windows validation](evidence/synthetic-mixer/windows/results.md) passed presentation, modal progress, idle, lifecycle and lock/RDP transition checks; real DPI transitions remain untested.
- FEATURE: `ui.Open` creates windows whose content is an immediate-mode view of labels and keyed animated meters, with any-goroutine `Invalidate`, per-window frame scheduling, monotonic one-shot animation pacing and no idle work once settled. Linux/amd64 renders on the CPU with pure-Go text (fallback, bidi, slight hinting, color emoji) under bounded per-window caches and presents through GTK and Cairo. See [ui.md](docs/current/ui.md), the [mixer example](examples/mixer/README.md) and the [stage 1 record](evidence/synthetic-mixer/stage-1.md).
- Added the no-cgo application/window runtime for Linux/amd64 (GTK 3) and Windows/amd64 (Win32), with independent windows and explicit window/resident application modes.
- Added bounded UI posting, owned cooperative tasks, failure propagation and shutdown diagnostics that remain observable while UI dispatch or final native release is stalled.
- Added the two-window lifetime example, controllable fake backend, lifecycle/concurrency and native ABI checks, and retained native validation on both hosts. See the [runtime contract](docs/current/runtime.md) and [final validation](evidence/foundation/stage-4.md) for behavior and platform limits.
